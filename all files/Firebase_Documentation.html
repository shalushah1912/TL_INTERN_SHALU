Getting Started

1

Install Firebase CLI

bash
npm install -g firebase-tools
firebase --version
2

Login & Initialize

bash
firebase login
firebase init
3

Install the SDK

bash
npm install firebase
4

Initialize in Your App

javascript
import { initializeApp } from 'firebase/app';

const firebaseConfig = {
  apiKey: 'YOUR_API_KEY',
  authDomain: 'your-app.firebaseapp.com',
  projectId: 'your-project-id',
  storageBucket: 'your-app.appspot.com',
  messagingSenderId: '123456789',
  appId: '1:123456789:web:abc123'
};

const app = initializeApp(firebaseConfig);

Firebase Authentication

Firebase Authentication provides backend services, easy-to-use SDKs, and ready-made UI libraries to authenticate users to your app. It supports authentication via passwords, phone numbers, popular federated identity providers, and more.

Supported Sign-in Providers

📧Email/Password
🔵Google
🍎Apple
📘Facebook
🐦Twitter / X
🐙GitHub
📱Phone SMS
👤Anonymous

Email & Password

javascript
import { getAuth, createUserWithEmailAndPassword, signInWithEmailAndPassword } from 'firebase/auth';

const auth = getAuth();

// Register a new user
createUserWithEmailAndPassword(auth, email, password)
  .then(userCredential => console.log('User:', userCredential.user))
  .catch(error => console.error(error));

// Sign in existing user
signInWithEmailAndPassword(auth, email, password)
  .then(userCredential => console.log('Signed in:', userCredential.user));

Google Sign-In

javascript
import { GoogleAuthProvider, signInWithPopup } from 'firebase/auth';

const provider = new GoogleAuthProvider();

signInWithPopup(auth, provider)
  .then(result => console.log('User:', result.user))
  .catch(error => console.error(error));

Listen to Auth State

javascript
import { onAuthStateChanged } from 'firebase/auth';

onAuthStateChanged(auth, user => {
  if (user) {
    console.log('Logged in:', user.uid);
  } else {
    console.log('User is signed out');
  }
});

Cloud Firestore

Cloud Firestore is a flexible, scalable NoSQL cloud database. Data is stored in documents organized into collections. It supports real-time listeners and offline data access for mobile and web.

  • Documents contain fields (key-value pairs)
  • Collections contain documents
  • Documents can have nested subcollections
  • Maximum document size: 1 MB

Initialize

javascript
import { getFirestore } from 'firebase/firestore';
const db = getFirestore(app);

Add a Document

javascript
import { collection, addDoc } from 'firebase/firestore';

const docRef = await addDoc(collection(db, 'users'), {
  name: 'Alice',
  email: 'alice@example.com',
  age: 25
});
console.log('Document ID:', docRef.id);

Read a Document

javascript
import { doc, getDoc } from 'firebase/firestore';

const docSnap = await getDoc(doc(db, 'users', 'userId123'));
if (docSnap.exists()) {
  console.log(docSnap.data());
} else {
  console.log('No such document!');
}

Update & Delete

javascript
import { updateDoc, deleteDoc, doc } from 'firebase/firestore';

// Update
await updateDoc(doc(db, 'users', 'userId123'), { age: 26 });

// Delete
await deleteDoc(doc(db, 'users', 'userId123'));

Query Documents

javascript
import { query, where, orderBy, limit, getDocs } from 'firebase/firestore';

const q = query(
  collection(db, 'users'),
  where('age', '>=', 18),
  orderBy('name'),
  limit(10)
);

const snapshot = await getDocs(q);
snapshot.forEach(doc => console.log(doc.id, doc.data()));

Real-time Listener

javascript
import { onSnapshot } from 'firebase/firestore';

const unsubscribe = onSnapshot(collection(db, 'users'), snapshot => {
  snapshot.docs.forEach(doc => console.log(doc.data()));
});

// Stop listening when done
unsubscribe();

Realtime Database

Firebase Realtime Database stores and syncs data as a single large JSON tree. Every connected client gets the same copy, updated in milliseconds. Best for simple real-time sync and low-latency scenarios.

💡Firestore vs Realtime DB: Use Firestore for complex queries and structured data. Use Realtime Database for simple, low-latency sync or when you need broad offline support.
javascript
import { getDatabase, ref, set, get, onValue } from 'firebase/database';

const db = getDatabase(app);

// Write data
await set(ref(db, 'users/user1'), { name: 'Bob', score: 100 });

// Read once
const snapshot = await get(ref(db, 'users/user1'));
console.log(snapshot.val());

// Listen in real-time
onValue(ref(db, 'users/user1'), snapshot => {
  console.log('Live data:', snapshot.val());
});

Cloud Storage

Firebase Cloud Storage is built for storing and serving user-generated content like photos, videos, and files. It's backed by Google Cloud Storage with built-in security rules.

Upload a File

javascript
import { getStorage, ref, uploadBytes, getDownloadURL } from 'firebase/storage';

const storage = getStorage(app);
const storageRef = ref(storage, 'images/profile.jpg');

// Upload
await uploadBytes(storageRef, file);

// Get public URL
const url = await getDownloadURL(storageRef);
console.log('File URL:', url);

Upload with Progress

javascript
import { uploadBytesResumable } from 'firebase/storage';

const uploadTask = uploadBytesResumable(storageRef, file);

uploadTask.on('state_changed',
  snapshot => {
    const progress = (snapshot.bytesTransferred / snapshot.totalBytes) * 100;
    console.log(`Upload is ${progress}% done`);
  },
  error => console.error(error),
  () => getDownloadURL(uploadTask.snapshot.ref).then(url => console.log(url))
);

Firebase Hosting

Firebase Hosting is production-grade web content hosting for developers. Deploy web apps and static content to a global CDN with a single command. Automatic SSL certificates included.

bash
# Initialize hosting
firebase init hosting

# Build your project, then deploy
firebase deploy --only hosting
🌍Your app goes live at https://your-project.web.app. Custom domains are supported with automatic SSL provisioning via Firebase Console → Hosting → Add Custom Domain.
  • Global CDN delivery from 100+ edge nodes
  • Automatic SSL/TLS certificates
  • One-command rollback to any previous deploy
  • Preview channels for staging environments
  • Integration with Cloud Functions for dynamic content

Cloud Functions

Cloud Functions for Firebase is a serverless framework that runs backend code in response to HTTPS requests or Firebase events — no server management required.

HTTP Function

javascript
const { onRequest } = require('firebase-functions/v2/https');

exports.helloWorld = onRequest((req, res) => {
  res.json({ message: 'Hello from Firebase!', timestamp: new Date() });
});

Firestore Trigger

javascript
const { onDocumentCreated } = require('firebase-functions/v2/firestore');

exports.onNewUser = onDocumentCreated('users/{userId}', event => {
  const data = event.data.data();
  console.log('New user created:', data.name);
  // Send welcome email, update stats, etc.
});

Deploy Functions

bash
firebase deploy --only functions
firebase deploy --only functions:helloWorld  # deploy specific

Security Rules

Firebase Security Rules protect your Firestore, Realtime Database, and Cloud Storage from unauthorized access. Rules evaluate on every request and are fully declarative.

Firestore Rules

firestore rules
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Users can only access their own data
    match /users/{userId} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }

    // Public posts: anyone can read, only author can write
    match /posts/{postId} {
      allow read: if true;
      allow write: if request.auth != null
                    && request.auth.uid == resource.data.authorId;
    }
  }
}

Storage Rules

storage rules
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    match /images/{userId}/{fileName} {
      allow read: if true;
      allow write: if request.auth.uid == userId
                    && request.resource.size < 5 * 1024 * 1024
                    && request.resource.contentType.matches('image/.*');
    }
  }
}
⚠️Always test your rules with the Firebase Emulator Suite and the Rules Playground in the Firebase Console before deploying to production.

Best Practices

Security

  • Never expose unrestricted API keys in client-side code
  • Write restrictive Firestore and Storage security rules from day one
  • Enable Firebase App Check to prevent unauthorized API access
  • Validate all data server-side in Cloud Functions
  • Use environment variables for sensitive config in Cloud Functions

Performance

  • Paginate Firestore queries with limit() and startAfter()
  • Avoid deeply nested structures in Realtime Database
  • Enable offline persistence for Firestore in mobile apps
  • Set minimum instances on Cloud Functions to reduce cold starts
  • Cache data client-side to minimize Firestore read counts

Cost

  • Use the Spark free plan during development
  • Set billing alerts in Google Cloud Console
  • Use batch writes to reduce write operation count
  • Avoid listening to large collections unnecessarily
  • Monitor usage dashboards weekly
