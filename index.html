Introduction

The Mechatronics Engineering Program commenced with an introductory session that laid the groundwork for the practical learning journey ahead. This first week focused on the development of a personal portfolio website — a real-world project combining web design, frontend development, and structured content planning.

During this week, I was introduced to core concepts in HTML5, CSS3, and vanilla JavaScript through the lens of building a functional, multi-page portfolio application. The project integrated professional design principles, interactive UI components, and a practical journaling system for tracking weekly engineering progress.

The week revolved around 4 major areas: page architecture, visual design systems, JavaScript-driven interactivity, and component-based thinking. Together, these topics created a strong foundation showing how front-end technologies are used in real engineering documentation and professional presentation contexts.

The portfolio itself serves a dual purpose — it showcases academic and project experience while also acting as a live engineering journal where daily progress, notes, photos, files, and code can be documented week by week.

1. Portfolio Website — Project Overview

The primary deliverable for Week 1 was the design and development of a personal engineering portfolio website for Shalu Shah, a Mechatronics Engineering student. The site was built as a single HTML file using no external frameworks, making it lightweight, portable, and easy to host.

The portfolio contains four main sections: Home (hero landing with profile stats), About (skills, experience timeline, and future aims), Journal (a structured weekly/daily progress tracker), and Contact (links and a closing quote). Navigation between sections is handled by a JavaScript-based Single Page Application (SPA) pattern — no page reloads occur.

The design adopts a dark, futuristic aesthetic with purple and teal accents. Typography uses Google Fonts: Playfair Display for headings, DM Sans for body text, and JetBrains Mono for code blocks.

2. HTML Structure & Page Architecture

The portfolio is built on semantic HTML5, with all four pages represented as <div> elements assigned unique IDs (page-home, page-about, page-report, page-contact). Only one page carries the .active class at a time, controlled by the showPage() JavaScript function.

Key structural concepts explored this week include: the sticky navigation bar, section-based content layout, nested view states (weeks → days → day detail inside the Journal page), and accessible form elements for note-taking and file uploads.

3. CSS Design System & Theming

A core feature of the portfolio is its use of CSS Custom Properties (variables) to define a centralized design system. All colors, fonts, spacing, and border radii are stored as variables in the :root selector, making the entire visual theme easy to update or modify from one location.

The design system includes dedicated variables for background layers (--bg, --bg2, --bg3), accent colors (--accent, --accent2, --teal, --gold), and text hierarchy (--text, --text2, --text3). This ensures visual consistency across all components without repetition.

4. JavaScript — SPA Navigation & State Management

The portfolio's interactivity is powered entirely by vanilla JavaScript, with no external libraries. The core pattern used is a Single Page Application (SPA) approach — all pages exist in the DOM simultaneously, and JavaScript controls which one is visible at any given time.

4.1 Page Navigation System

The showPage(p) function is the central navigation controller. It removes the .active class from all pages, then adds it to the target page. It also updates the navigation bar to highlight the current section.

  • MDN — querySelectorAll
  • MDN — classList API
  • MDN — CSS @keyframes Animations
function showPage(p) {
  document.querySelectorAll('.page').forEach(x => x.classList.remove('active'));
  document.getElementById('page-' + p).classList.add('active');
  document.querySelectorAll('.nav-links button').forEach(b => {
    const map = { home:'home', about:'about', report:'journal', contact:'contact' };
    b.classList.toggle('active', b.textContent.toLowerCase().includes(map[p]));
  });
  if (p === 'report') showWeeksView();
}

4.2 Journal State Management

The Journal page uses a three-level nested navigation system: Weeks view → Days view → Day Detail view. Each level is a separate <div> whose visibility is toggled using the display style property. The current week and day are tracked with the module-level variables currentWeek and currentDay.

Data for each day (notes, photos, files, code snippets) is stored in a plain JavaScript object (storage = {}) keyed by week-day combinations (e.g., w1d3 for Week 1, Day 3). This is in-memory storage — data resets on page refresh. A future improvement would use localStorage to persist entries.

4.3 Notes, Photos, Files & Code Modules

Each day entry has four interactive modules managed by dedicated JavaScript functions:

  • Notes: addNote(), renderNotes(), delNote(i) — text notes with timestamps.
  • Photos: addPhotos(inp), renderPhotos(), delPhoto(i) — image uploads using FileReader API converted to base64.
  • Files: addFiles(inp), renderFiles(), delFile(i) — file metadata logging (name, size, timestamp).
  • Code: saveCode(), renderCodes(), delCode(i) — code snippets with language selector and HTML escaping.
  • MDN — FileReader API
  • MDN — Textarea Element

4.4 Tab Switching System

Within the Day Detail view, a tab system controls which content panel (Notes, Photos, Files, Code) is visible. The switchTab(tab, btn) function iterates over all four panel IDs and hides all except the selected one, while also toggling the .active class on the corresponding tab button.

  • MDN — HTML id Attribute
  • MDN — CSS display Property
function switchTab(tab, btn) {
  ['notes','photos','files','code'].forEach(t => {
    document.getElementById('tab-' + t).style.display = (t === tab) ? '' : 'none';
  });
  document.querySelectorAll('.tab').forEach(b => b.classList.remove('active'));
  if (btn) btn.classList.add('active');
}

5. Weekly Journal & Progress Tracker

The Weekly Journal is the most feature-rich section of the portfolio. It provides a structured system for logging daily engineering activities across 4 weeks, with 6 working days per week (Monday–Saturday).

Each day entry supports four types of content: written notes (with Enter-key shortcut support), photo uploads (rendered as a responsive image grid), file attachments (logged by name, size, and time), and code snippets (with a language selector for Arduino/C++, Python, JavaScript, C, and Other). This makes the journal suitable for documenting practical engineering lab sessions in detail.

6. Responsive Design & Layout Techniques

The portfolio uses CSS Grid with auto-fit and minmax() to create layouts that automatically reflow on smaller screens without explicit breakpoints. This ensures the site remains usable on mobile devices, tablets, and desktops.

6.1 Grid Layouts

Two primary grid classes are used: .grid-2 (minimum 280px columns) for two-column card layouts such as Aims, and .grid-3 (minimum 200px columns) for three-column stat cards. Both collapse to a single column on narrow screens automatically.

Common CSS layout patterns used: display:grid, repeat(auto-fit, minmax()), gap, flexbox

Navigation bars, button groups, and contact grids all use CSS Flexbox with flex-wrap:wrap to gracefully adapt to available width. The hero section uses clamp() for fluid typography — the heading scales from 3rem to 6rem based on viewport width.

Common CSS properties used: display:flex, flex-wrap:wrap, gap, clamp(), align-items, justify-content

The portfolio features several reusable UI components designed with consistent visual language and smooth micro-interactions. Each component was crafted with hover states, transitions, and clear visual hierarchy.

Key components built include: stat cards (home page), skill tags (about page), timeline items (experience section), aim cards with icon badges, week/day cards with animated dot indicators, upload boxes with dashed borders, entry items for notes/files/code, and photo thumbnails with overlay delete buttons.

8. Deployment & File Structure

The portfolio is designed as a self-contained single HTML file — all CSS is embedded in a <style> block and all JavaScript is embedded in a <script> block at the end of the document. The only external dependency is Google Fonts, loaded via a <link> tag.

This architecture means the portfolio can be deployed by simply uploading one file to any web host, opened locally in a browser, or shared directly. The following settings and considerations were studied:

  • Single-file architecture — no build tools or bundlers needed
  • Google Fonts loaded via CDN (requires internet connection)
  • All images referenced via relative paths (e.g., ./images/photo.jpg)
  • JavaScript data stored in-memory (resets on refresh — no backend required)
  • Future improvement: use localStorage to persist journal entries
  • Future improvement: add a manifest and service worker for offline PWA support
  • Compatible with GitHub Pages, Netlify, Vercel, and any static host
  • No framework dependencies — works in any modern browser
  • Minification can reduce file size for production deployment
  • Meta viewport tag ensures correct rendering on mobile devices
  • UTF-8 charset declaration ensures proper text encoding
  • GitHub Pages — Free Static Hosting

11. Personal Reflection

Week 1 was an exciting and intensive introduction to frontend web development through the lens of building something personally meaningful — my own engineering portfolio. What stood out most was the realization that a single HTML file, when thoughtfully structured, can deliver a fully interactive, multi-page application experience without any framework or build tool.

The most challenging aspect was designing the Journal's nested navigation system — managing three layers of view state (weeks, days, day detail) with clean transitions required careful planning of DOM structure and JavaScript logic. Understanding how to use a simple object as an in-memory database, keyed by week-day pairs, was a particularly valuable pattern that I can apply in future projects.

This week's work connects directly to my goals as a Mechatronics engineer — the ability to document, communicate, and present technical work clearly is as important as the engineering itself. The portfolio now serves as both a professional showcase and a practical tool for logging my engineering learning journey going forward. I am eager to expand it with real project content, photos, and code snippets as the program progresses.
